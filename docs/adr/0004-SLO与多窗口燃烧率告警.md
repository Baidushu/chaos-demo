# ADR-0004：采用 SLO + 多窗口燃烧率告警，替代拍脑袋阈值告警

- 状态：已采纳（2026-08）
- 背景：原有告警为固定阈值（如 5xx 速率 > 0.15/s），与用户期望无关
- 决策人：仓库作者（个人项目）

## 背景

阈值告警的两个经典问题：阈值怎么定没有依据（为什么是 0.15 不是 0.2）；
同一阈值对不同流量水位语义完全不同（10 QPS 和 1000 QPS 下 0.15/s 的
错误率是天壤之别）。

## 决策

采纳 SRE 方法论（见 `docs/slo.md`）：

1. 定义 SLI（可用性 = 非 5xx 占比；延迟合规 = ≤0.5s 占比）与 30 天窗口的
   SLO（99.9% / 99.0%）。
2. 由错误预算推导告警：**多窗口/多燃烧率**法——
   快烧 14.4×（1h+5m 双窗，page）与慢烧 6×（6h+30m 双窗，warning）。
3. recording rules 预聚合各窗口比率（`slo-burn-rate-recording` 组），
   告警表达式引用录制指标，查询开销与表达式复杂度可控。

## 理由

- 告警有了第一性依据：烧预算的速度，而不是任意绝对值。
- 双窗口机制天然抑制短时抖动（压测/混沌演练期间的瞬时 5xx 不会误报 page）。
- 与 CI 门禁形成两层防线的清晰分工：门禁回答「这版能不能发」
  （单轮压测、分钟级、阈值严），SLO 回答「线上是否偏离承诺」
  （30 天统计、预算制）。

## 代价与权衡

- 直方图桶位尚未与 450ms 门禁值对齐（当前用 0.5s 桶近似，见 slo.md §6）。
- 错误预算只告警、不硬约束（预算耗尽不自动 freeze 发布）——个人项目
  无此流程需求，企业场景应配 budget policy。
- 30 天滚动窗口的精确实现需要长期指标存储（当前 Prometheus 短保留，
  告警用 1h/6h 窗口近似推导，方法论一致）。
